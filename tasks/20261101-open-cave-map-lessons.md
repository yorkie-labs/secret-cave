# Lessons · 이어진 동굴 지도

- 사용자가 작업 중에 두 번 방향을 바꿨다("방 형태가 답답하다" → 넓은 광장 + 넓은 길, 잠금 없음 / "카메라가 가깝다" → 30 m, 높은 절벽). 둘 다 *느낌*에 대한 말이었다.
  → 크기·카메라처럼 느낌을 좌우하는 수치는 처음부터 스크린샷 두세 장(기본 카메라, 줌아웃, 예전 것)으로 사용자에게 먼저 보여 줄 거리로 만든다. 방/관 구조를 만들기 전에 "열린 느낌" 기준(카메라에서 다음 공간이 보이는가, 주인공을 가두는가)을 정한다.
- 큰 지도 배치는 무작위 걷기를 그냥 하면 일자로 뻗어 200 m 안에 안 들어갔다(성공 3%). 후보 여러 개 중 지도가 가장 작게 남는 것을 고르니 길이 접혀 돌아왔다. 연속 갈림길(2×2 길)은 평면에서 엇갈리니 갈림목을 넣는다.
  → 배치 알고리즘은 실패 이유를 세는 진단(어느 칸에서, 어떤 규칙 때문에)부터 만들고 고친다. 추측으로 수치를 바꾸지 않는다.
- Rapier는 지운 몸체의 핸들을 재사용한다. 짓는 도중 지운 충돌체를 scope가 다시 지우면 새 몸체가 지워지고 wasm이 `unreachable`로 멈춘다.
  → 몸체 지우기는 JS 객체에 표시해 두 번 지우지 않는다. 열린 채 시작하는 문은 충돌체를 만들지 않는다.
- 시나리오가 통과해도 기능이 안 보일 수 있다(자석: 줍기 모델이 y만 따라가서 조각이 실제로 날아오지 않았고, 방을 나갈 때 자동 줍기가 결과만 맞춰 줌).
  → "날아온다" 같은 동작은 결과(줍힌 개수)만 보지 말고 움직임(위치 변화)을 확인한다.
- 이미 5191을 쓰는 서버가 사용자 것인데 `npx vite`를 띄웠다가 포트 때문에 실패하면서도 의존성 캐시(`node_modules/.vite/deps`)를 지웠다.
  → 서버를 띄우기 전에 `lsof -i :5191`과 그 프로세스의 부모를 먼저 본다. 사용자 서버면 띄우지 말고 그대로 쓴다. 고쳐야 하면 프로세스를 죽이지 말고 `vite.config.js` touch로 그 서버가 스스로 다시 시작하게 한다.
